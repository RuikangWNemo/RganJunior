# 阿柑少年微信公众号全量归档计划

## 目标

完整枚举并归档“阿柑少年”微信公众号已公开发表的全部内容，形成可审计、可重复执行、可继续迁移到网站的本地素材库，并把本次行动方法沉淀为同类公众号归档范本。

## 范围口径

- 包含：所有公开发表记录；多图文中的每一篇；标题、作者、摘要、发布时间、原始链接、封面、正文 HTML、正文图片及其他可获取媒体。
- 产物：原始 HTML、清洗后的 HTML、Markdown、元数据、媒体文件、全局清单、完整性报告。
- 暂不包含：未发表草稿、粉丝资料、私信、统计数据等非公开或个人数据。
- 不对公众号执行发布、删除、群发、改菜单等写操作。

## 采集策略

1. 优先使用公众号官方后台/API枚举发表记录，因为它是账号自身的权威清单。
2. 若 API 未配置或权限不足，使用用户已登录的微信公众平台后台读取“发表记录”。
3. 对每个公开文章 URL 使用文章提取器解析；必要时用浏览器保存页面作为降级方案。
4. 每篇文章独立落盘，先保存原始证据，再做内容转换；失败不阻断全批次，统一进入重试清单。
5. 以 `__biz + mid + idx + sn` 或规范化 URL 哈希作为稳定标识，避免标题重名造成覆盖。

## 验收条件

- 权威入口显示的全部发表记录均已枚举，且多图文已逐篇展开。
- 每篇至少有元数据和原始链接；可访问文章同时有正文 HTML 与 Markdown。
- 所有可下载封面和正文图片均已本地化，正文引用可离线解析。
- 清单计数可解释：总数 = 成功 + 部分成功 + 明确失败；失败项均有原因和重试入口。
- 随机抽查早期、中期、近期文章，标题、日期、正文顺序和图片一致。

## 关键决策

| 决策 | 原因 |
|---|---|
| 只做只读采集 | 防止误发、误删或改变公众号状态 |
| 官方后台/API 优先 | 可获得最完整、可分页且可核对的发表清单 |
| 原始层与转换层并存 | 既保留证据，又方便下一步网站迁移 |
| 每篇独立目录 | 便于增量更新、失败重试和媒体相对引用 |
| 失败继续批处理 | 单篇访问限制不应阻断全量归档 |
