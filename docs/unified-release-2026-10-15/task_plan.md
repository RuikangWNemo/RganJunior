# 统一版本整理与发布

用户授权：整理本地 worktree，合并各自更新，推送 GitHub，再部署到 Vercel。所有构建在本机完成，仅上传预构建成品；不在 ECS 或 GitHub 构建、部署。

- [ ] 核对远端、生产部署与各 worktree 的源码和未提交文件。
- [ ] 保存本地主目录完整源码快照，保留既有发布分支历史与忽略的配置。
- [ ] 清理过期可重建产物与不存在的 worktree 记录，创建统一发布分支。
- [ ] 合并最新正式版本及本地更新；关闭 Git 自动部署，GitHub CI 只做代码检查。
- [ ] 完成完整测试、类型检查、lint、本机生产预构建及关键页面浏览器验收。
- [ ] 推送可追踪的分支/主版本与发布标签，不强推、不丢失远端提交。
- [ ] 上传预构建成品，验证暂存生产部署后 promote 到正式域名。
- [ ] 核验正式站、API、资源哈希并整理本地 worktree/版本记录。

当前问题：磁盘仅约 153MB 可用；先清理旧发布 worktree 的 node_modules/dist/.vercel/output 等可重建产物。主目录源码、版本历史、环境文件、原始图片和发布证据均保留。GitHub CLI 的现有 token 报失效，后续核对实际 Git 推送认证；Vercel MCP 403，改用同团队的既有 CLI 登录只读核验。
