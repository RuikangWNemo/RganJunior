# 伙伴星球广场设计

日期：2026-08-08

## 背景

当前伙伴页以三列资料卡呈现正式成员，信息清楚，但缺少“大家共同存在于一个社群空间”的整体感。希望将伙伴页升级为类似社交星球的可探索广场：成员分布在一个可以旋转的星球上，用户通过拖拽、选择和资料面板认识伙伴。

现有 `list_community_people` 只提供经隐私策略允许展示的成员姓名、自然名、简介、地点、头像引用和加入时间，不提供可公开展示的成员关系图。因此第一版不会用连线暗示真实关系；星轨只承担空间与视觉引导。

## 已确认目标

- 每位可见伙伴成为星球表面的一颗可选择星点。
- 星球支持缓慢自转、拖拽旋转和轻微惯性。
- 点击星点后将该伙伴转到前方，并显示资料与“发消息”操作。
- 自己的节点具有独立识别，不显示给自己发消息的操作。
- 星点之间的线条只作为装饰性星轨，并在界面中明确说明其非关系含义。
- 保留完整名单模式，兼顾键盘、辅助技术、低性能设备与快速浏览。
- 不修改现有人员可见性、消息、认证、成员资格或 Supabase 权限逻辑。

## 方案比较

### 方案 A：WebGL 3D 星球 + DOM 资料面板（采用）

使用项目已有的 React Three Fiber、Drei 和 Three.js 构建立体球体、节点、星轨和旋转交互；资料面板、模式切换和伙伴索引继续使用普通 DOM。

优点是空间感、旋转与深度最自然，同时资料展示和操作仍保持清晰可访问。代价是需要控制 WebGL 体积、设备像素比、动画循环和降级路径。

### 方案 B：CSS 3D 节点球

使用 DOM 元素和 CSS 3D transform 构造球面。文字清晰、实现较轻，但遮挡、深度、拖拽惯性和节点数量增加后的维护性不如 WebGL。

### 方案 C：2D Canvas 球面投影

在 Canvas 中计算节点投影模拟球体。性能可控，但命中测试、键盘操作、资料提示和可访问语义需要另建一套交互层。

## 页面结构

伙伴页继续使用现有 `CommunitySurface`，内容区改为：

1. 顶部模式栏：`星球 / 名单`、旋转暂停/继续、重置视角和星轨说明。
2. 星球模式：桌面使用星球舞台与右侧资料面板；移动端使用单列星球舞台和底部资料卡。
3. 伙伴索引：在星球下方提供可键盘操作的成员名称按钮，选择后与星球节点同步。
4. 名单模式：保留现有资料卡内容与消息入口，作为完整替代视图。

首次加载默认进入星球模式。视图模式只属于当前页面状态，不写入账号资料或远端数据库。

## 星球视觉

- 暖米白环境继续承接 Community 外壳。
- 球体使用低透明度森林绿和细线经纬纹理，避免复制 Soul 的蓝紫视觉。
- 普通伙伴使用森林绿、暖金色与米白星点；当前用户使用柑橘橙光环。
- 节点位置依据成员稳定 ID 通过 Fibonacci sphere 算法生成，同一批成员每次进入位置一致。
- 星轨从稳定节点集合生成少量弧线，透明度低，不形成真实关系暗示。
- 只为当前悬停、聚焦或选中的伙伴显示名称标签，避免 40 个 DOM 标签持续覆盖画布。

## 交互

- 星球在无操作时缓慢自转。
- 鼠标或单指拖拽控制旋转，释放后保留短暂惯性；不劫持页面滚动，不启用滚轮缩放。
- 点击节点或伙伴索引会将成员平滑转到相机前方，并更新资料面板。
- 用户主动暂停后不再自动恢复；拖拽期间临时暂停，松手后按原状态继续。
- “重置视角”恢复初始构图并清除选中状态。
- 点击“发消息”复用现有 `createDirectConversationWithPerson` 与消息路由。

## 数据与错误处理

- 继续并行读取 `listCommunityPeople()` 与 `getMyCommunityProfile()`。
- 头像媒体尚无可直接使用的公开 URL 时，以自然名或显示名首字作为稳定节点标识。
- 加载状态使用星球舞台骨架；读取失败继续提供重试；无成员时沿用现有空状态。
- 3D 模块加载失败、WebGL 不可用或用户选择减少动态效果时，页面仍可进入名单模式。

## 性能与可访问性

- 3D 模块通过 `React.lazy` 延迟加载，只在伙伴页的星球模式下载。
- 设备像素比限制在桌面 1.5、移动端 1.25 左右。
- 星球离开视口时暂停帧循环；页面隐藏时停止自转。
- 动画只改变 WebGL 对象的 quaternion、scale 与 opacity，不连续修改 DOM 布局。
- `prefers-reduced-motion` 下关闭自转与惯性，保留静态可选星球并默认提供名单入口。
- Canvas 提供说明性可访问名称，完整成员选择、资料和消息操作由 DOM 索引与资料面板提供。

## 响应式

- 桌面：星球舞台约占 70%，右侧资料面板约占 30%，舞台高度约 36–42rem。
- 平板：星球在上，资料面板在下，保持足够触控区域。
- 手机：舞台使用接近方形的比例，伙伴资料以底部卡片出现，模式控制保持 44px 触控目标。
- 名单模式继续使用当前响应式卡片网格。

## 验证

- 单元测试覆盖稳定球面位置、视觉星轨生成和同一成员集合的确定性。
- 组件测试覆盖星球/名单切换、伙伴索引选择、本人状态和发消息入口。
- 测试 3D 延迟加载失败时名单仍可使用。
- 运行 Community 聚焦测试、完整 Vitest、针对性 ESLint、生产构建。
- 浏览器验证桌面与 390px 手机视口的拖拽、选择、资料面板、模式切换、无横向溢出和 reduced-motion。
