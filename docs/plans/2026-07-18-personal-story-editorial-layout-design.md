# 四篇个人成长故事编辑排版设计

## 目标与范围

仅优化四篇 `growth-story` 类型的个人成长故事；项目发起信继续使用现有项目说明版式。目标是把微信长文整理成层级清楚、照片有节奏、适合手机长时间阅读的人物特写，同时建立可复用的内容导入规则。

## 已确认方向

采用方案 A：编辑杂志式叙事系统。

- 文章由人物标题区、导语、章节正文、媒体段落和后续阅读组成；
- 文字保持单一稳定阅读轴，照片可以根据方向和组合形成不同宽度；
- 不使用轮播、灯箱或需要学习的交互；
- 不改写故事正文，不改变照片顺序；
- 四篇故事共享同一系统，人物与内容差异由照片和文字自然体现。

## 页面结构

成长故事详情页使用独立的 `growth-story` 视觉变体：

1. 顶部返回入口保持低调；
2. 类型、发布日期和作者形成紧凑眉题；
3. 标题使用更明确的编辑层级，导语控制宽度；
4. 封面与正文之间建立稳定过渡，不让封面直接压入长文；
5. 正文段落沿窄阅读轴排列；
6. 章节标题作为清晰的叙事节点；
7. 文章末尾的原文入口与下一篇推荐弱化为阅读收束，而非营销模块。

项目发起信不套用这套变体。

## 图片系统

导入阶段根据原图 `width` 与 `height` 标注媒体方向，并识别相邻的纯图片容器。

- 横图：作为主要场景照片，可占满正文媒体宽度；
- 单张竖图：手机端不再铺满屏幕，使用较窄的居中画幅；
- 连续两张竖图：在手机端组成双列照片组，减少垂直堆叠；
- 三张及以上连续照片：按两列网格流动，最后一张保持自然对齐；
- 混合方向照片：保留顺序，根据方向形成宽图与窄图交替，不强行裁切人物；
- 图注：紧贴所属图片或图片组，使用较小字号与弱色，不单独占据正文节奏；
- 所有照片保持原始比例，使用 `object-fit: cover` 仅限固定比例缩略展示，不裁切正文单图。

手机端的目标不是把所有照片缩成小图，而是通过“横图展开、竖图收束、成组并列”建立节奏。桌面端允许媒体适度突破文字列，但正文宽度保持稳定。

## 内容语义与导入

内容导入脚本承担可重复的机械标注：

1. 为图片容器添加横图、竖图或近方图类别；
2. 把连续纯图片容器包装为媒体组；
3. 保留现有章节标题和图注语义；
4. 对四份现有成长故事运行相同处理；
5. 不处理 `project-letter`，避免项目发起信被意外改版。

页面组件只根据故事类型添加根级变体类；具体照片排版由内容语义类和 CSS 完成，避免在 React 中硬编码某篇文章的图片编号。

## 响应式规则

- 手机（约 390px）：正文保留舒适侧边留白；竖图单张明显窄于正文，连续竖图双列；图片组间距小于章节间距；
- 平板：照片组保持双列或按内容方向展开；
- 桌面：文字列约 40–43rem，横图可扩展到更宽媒体列，竖图保持克制宽度；
- 页面不得出现横向滚动，图片尺寸属性继续用于减少布局跳动。

## 视觉语言

沿用网站现有纸张色、森林绿、衬线标题和 8px 圆角，不新增设计依赖。高级感来自比例、留白和节奏，而不是阴影、渐变或装饰堆叠。章节标题、眉题、图注与正文形成清晰但克制的四级层次。

## 验收标准

- 仅四篇成长故事启用新排版；
- 390px 视口下竖图不再连续全宽堆叠；
- 相邻竖图能够成组展示且顺序不变；
- 横图、竖图、图注和章节之间层级清楚；
- 桌面端正文与媒体宽度形成稳定的双尺度；
- 四篇文章均无横向溢出、破图或内容缺失；
- 项目发起信视觉和内容保持不变；
- 导入脚本、测试、Lint、生产构建及浏览器检查通过。
