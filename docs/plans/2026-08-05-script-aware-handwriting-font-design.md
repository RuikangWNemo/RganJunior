# 中西文手写字体分流设计

## 目标

让网站按字符类型自动选择字体：英文、数字和常用西文标点使用 TanukiMagic，中文保留“悄悄话手写”，并修正“信”等已确认的错误字形映射。

## 已确认方案

- 将 TanukiMagic 声明为字体栈中的第一字体，只开放完整的西文字符区段和指定修正字符。
- TanukiMagic 覆盖 Basic Latin、Latin Extended、常用西文标点、货币符号、箭头、带圈字母数字、全角西文字符，以及 `信`（U+4FE1）。
- “悄悄话手写”作为第二字体，继续承载其余中文字符。
- `信` 使用 TanukiMagic 的正常汉字字形，避开“悄悄话手写”源文件中的信封图标映射。
- 字体路由通过 `@font-face` 的 `unicode-range` 和统一字体栈完成，不要求逐个组件包裹字符。
- 等宽代码内容继续保持等宽字体。

## 实施计划

1. 从 TanukiMagic 原始文件生成覆盖完整西文区段与 `信` 的 WOFF2。
2. 在全局样式中声明 TanukiMagic Web，并将其置于中英文字体栈首位。
3. 保持现有 Tailwind 字体变量接口不变，使正文、标题和组件自动获得相同规则。
4. 验证子集包含目标区段内原字体的全部字符，并确认 `信`、`1`、英文和普通中文分别命中正确字形。
5. 运行测试、代码检查、生产构建和浏览器实测。

## 验收标准

- `ABC abc 123` 使用 TanukiMagic。
- `相信` 中的“相”使用中文手写字体，“信”显示为正确汉字而非信封图标。
- 未来新增的英文、数字及常用西文符号无需重新生成字体。
- 页面无字体加载错误，测试与生产构建通过。
