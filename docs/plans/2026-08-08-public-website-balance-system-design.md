# 阿柑少年公开网站平衡设计系统

## 状态

- 设计方向：已确认
- 实施策略：先制作与正式路由隔离的设计评审页，确认后再渐进迁移生产页面
- 视觉基准：保留现有“项目”板块的温暖田野编辑风格
- 核心目标：统一字号、字体角色、色块节奏、横向子菜单和图文模块

## 研究基线

本设计使用现有项目页作为品牌基准，用成熟设计系统与可访问性标准校准数值：

- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：普通文字对比度至少 `4.5:1`，大型文字至少 `3:1`；页面需支持 320 CSS px 宽度的单列回流。
- [USWDS Typography](https://designsystem.digital.gov/components/typography/)：使用受控的行长和行高维持阅读节奏；长文本行高不低于 `1.5`。
- [USWDS Design Tokens](https://designsystem.digital.gov/design-tokens/)：从有限、可命名的字体、色彩和间距 token 中取值，避免页面级任意值。
- [Carbon 2x Grid](https://carbondesignsystem.com/elements/2x-grid/overview/)：使用 8px 基础单位和稳定栅格建立水平、垂直节奏。

## 现状审计

### 文字

- “项目”顶部当前使用约 14.4px 无衬线标签配最高 105.6px 手写主标题，层级断层过大。
- “阿柑少年的项目”与“每一次加入，都从真实生活开始。”尚未形成用户期望的两层手写标题。
- 首页部分章节同时使用过多视觉字号，页面之间也没有共享同一类型 token。

### 颜色

- 首页、项目与加入页面分别维护近似但不同的米色、橙色和绿色。
- 原亮橙 `#EA6A2A` 在米色上的对比度约为 `2.90:1`，即使作为大文字也略低于 WCAG AA 的 `3:1`。
- 项目页最后一段使用偏黑绿色，与“加入我们”的 `#006644` 缺乏统一。

### 模块

- 项目页已经具备较好的左右交替图文结构和横向章节导航，但它们还没有成为全站共享的模块。
- 首页“我们相信”采用 7/5 栅格与不对称排列，但条目尺度、阅读顺序和项目页的关系不够清楚。

## 视觉方向

采用“温暖田野编辑系统”：

- 70% 标准秩序：共享类型、颜色、间距、栅格与内容合约。
- 30% 编辑变化：图文交替、主次内容、满屏摄影和少量不对称。

不改变现有项目板块的品牌气质，不转向 SaaS 卡片墙、儿童网站或冷淡的奢侈品排版。

## 文字系统

### 字体角色

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| Brand Hand | `TanukiMagic Web`, `Rgan Round Glyph Patch`, `Qiaoqiaohua Handwriting` | 短大标题、长小标题、模块短标题 |
| Body Sans | `Noto Sans SC`, `PingFang SC`, `Microsoft YaHei`, system-ui | 介绍、正文、导航、链接、时间、地点与作者 |

长介绍不使用手写字体。英文手写标题超过两行时回退到 Body Sans。

### 顶部三层标准

| 层级 | 示例 | Desktop | Tablet | Mobile | 行高 |
| --- | --- | ---: | ---: | ---: | ---: |
| 短大标题 | 阿柑少年的项目 | 60px | 52px | 40px | 1.06 |
| 长小标题 | 每一次加入，都从真实生活开始。 | 34px | 30px | 26px | 1.35 |
| 介绍正文 | 从两天的初次相遇…… | 17–18px | 17px | 16px | 1.8–1.9 |

普通内容框不超过三个主要字号。作者、时间和地点优先使用颜色、字重和位置区分，不再创建额外视觉层级。

### 内容限制

- 大标题：中文建议不超过 10–12 字，最多两行。
- 小标题：建议不超过 24 字，桌面最多两行，手机最多三行。
- 普通中文正文：每行约 32–38 字。
- 顶部间距：大标题至小标题 24px，小标题至正文 24px，段落间 12–16px。
- 标题和长正文默认左对齐。

## 标准顶部

顶部延续项目页的左右结构，桌面为约 7:5：

```text
[短大标题 / 长小标题 / 介绍正文] [真实人物或背景介绍]
```

- 左侧使用完整的三层文字系统。
- 右侧长介绍统一为 17–18px Body Sans，不再使用大号手写引语。
- 保留橙色竖线作为项目风格的识别元素。
- 桌面上下留白 96–120px，手机 64–80px。
- 页面默认容器为 1152–1248px。

## 颜色系统

### Foundation Tokens

| Token | 色值 | 用途 |
| --- | --- | --- |
| `paper` | `#F7F4ED` | 页面顶部与默认内容背景 |
| `peach` | `#F6DAC5` | 第一个项目、邀请型内容 |
| `warm-sand` | `#E2D4BF` | 进入深色前的过渡 |
| `join-green` | `#006644` | 最后项目、加入与行动区域 |
| `ink` | `#292A27` | 主要文字 |
| `muted-ink` | `#66625C` | 辅助说明 |
| `brand-orange` | `#E16524` | 大型手写标题和装饰线 |
| `action-orange` | `#B94718` | 小链接、标签和按钮文字 |
| `soft-border` | `#D9D3C8` | 分隔线和滑动导航边界 |

### 页面色块节奏

```text
Paper 顶部介绍
→ Peach 项目 01
→ Paper 项目 02
→ Warm Sand 项目 03
→ Join Green 项目 04
```

禁止在这些色块之间使用渐变。同一页不再创建新的近似米色、橙色或绿色。

### 对比度

| 组合 | 对比度 |
| --- | ---: |
| Ink / Paper | 13.14:1 |
| Muted Ink / Paper | 5.51:1 |
| Brand Orange / Paper | 3.14:1 |
| Action Orange / Paper | 4.81:1 |
| Paper / Join Green | 6.41:1 |
| Ink / Peach | 10.83:1 |
| Ink / Warm Sand | 9.90:1 |

Brand Orange 只用于大型文字和装饰。Peach 和 Warm Sand 上的小字号橙色使用 Action Orange。Join Green 上的主文字使用 Paper。

## 横向子菜单

以现有 Programs Section Nav 为唯一视觉基准：

- 在主导航下方 sticky：桌面 `top: 80px`，手机 `top: 64px`。
- 桌面高 60px，手机高 56px。
- Paper 背景和 Soft Border 底线。
- 15px / 500 Body Sans。
- Active 同时使用 Action Orange 文字和 2px 下划线。
- 不使用 pill、色块按钮或阴影。
- 手机保持单行横向滚动，隐藏 scrollbar，active item 自动滚动到可见区中部。
- 点击高度不小于 44px；键盘焦点必须可见。

## 内容模块

所有标准内容模块共享一个 contract：

```text
Photography + Title + Subtitle / Body + Context / Link
```

### A · Standard Media Text

项目、首页“我们相信”、人物和行动内容的默认模块。

- 桌面使用 12 栏：图片 7 栏，文字 5 栏，间距 56–80px。
- 图片使用 4:3 或 3:2，高度控制在 400–520px。
- 模块上下留白 72–96px。
- 图片不放入白色 card，不使用 shadow，radius 统一为 12px。
- 连续条目可交替图文位置，但手机总是图片在前、文字在后。
- 概览内容限制：标题约 12 字，小标题约 24 字，正文 80–140 字。
- 常见桌面画幅下尽量完整呈现一个条目；不使用强制高度裁切超长内容。

### B · Feature + Secondary

适合一个明确主内容配一个次内容。

- 主内容约 8 栏，次内容约 4 栏。
- 次内容通过减少 slots 和文字量建立主次，不把所有元素等比缩小。
- 一个章节中最多出现一次。

### C · Story Pair

仅用于两条同级、简短的内容。

- 桌面双列，图片在上，短标题和说明在下。
- 超过两条时拆分章节或回到 Standard Media Text。
- 禁止扩展成四张、六张同构 card wall。

### D · Full-width Photo Essay

横排满屏真实照片，下方配少量文字，用作长页面的视觉换气。

- 图片宽 `100vw`，不使用 radius、border 或 shadow。
- 桌面优先 16:7，高度 460–620px；手机转换为约 4:3，可配置独立 focal point。
- 文字在图片下方的标准容器内，默认不覆盖在复杂照片上。
- 手写短标题 24–30px，Body Sans 说明 16–18px，可加同层级地点、时间或摄影说明。
- 不放置多个按钮、badge 或长文。
- 每个长页面建议一次，最多两次。

## 响应式规则

### 1440px Desktop

- 容器 1152–1248px，12 栏。
- 顶部、Standard Media Text 和 Feature + Secondary 使用完整左右构图。
- 一个标准条目在常见 1440 × 900 画幅中尽量完整显示。

### 820px Tablet

- 顶部可保留紧凑双列；条目模块在文字行长过窄时切换为上图下文。
- Feature + Secondary 保留主次，但允许改为错落纵向流。
- 子菜单保持横向滚动。

### 390px Mobile

- 单列，页面无二维滚动。
- 图片总是先于文字。
- 正文不小于 16px，交互高度不小于 44px。
- 满屏照片使用手机专用 crop，文字仍位于图片下方。

## 隔离评审页

评审页不接入正式 React 路由，不修改正式页面、内容、SEO 或交互。它需要包含：

1. 当前项目顶部与新标准的左右对照。
2. 三层文字标准和真实长度文案。
3. Paper → Peach → Paper → Warm Sand → Join Green 色带与 token 标注。
4. 标准横向子菜单的 active、focus 和 overflow 状态。
5. 两组交替 Standard Media Text。
6. Feature + Secondary 组合。
7. Full-width Photo Essay。
8. 1440px、820px 和 390px 三种画幅的评审说明。

## 验收标准

- 任一普通内容框不超过三个主要字号。
- 项目顶部的大小标题均使用手写字体，长介绍使用 Body Sans。
- 色块顺序、色值和文字组合符合本文档。
- 横向子菜单能通过鼠标、键盘与触控使用。
- 标准条目、主次组合和满屏照片在三种画幅中都保留完整内容和清晰阅读顺序。
- 页面在 320 CSS px 宽度下不出现页面级横向滚动。
- `prefers-reduced-motion` 下取消非必要的平滑滚动和过渡。
- 不覆盖或回滚当前工作区中的其他改动。
