# 社区文章高级协作编辑器设计

日期：2026-08-08

## 背景

社区文章目前使用标题、摘要和正文文本框完成编辑，正文以纯文本保存在 `field_notes.content`。这种实现能够支撑基础投稿，却无法提供结构化内容、富文本排版、图片与文件块、评论、版本历史或多人同时写作，也无法形成接近飞书文档的创作体验。

本次在保留现有 Supabase Auth、Membership、文章审核和发布流程的基础上，引入开源的 BlockNote Core、Yjs 与 Hocuspocus，建立支持完整双语、实时多人协作、离线恢复和版本管理的社区文章工作台。

## 目标

1. 让用户通过块编辑器自由组织文章，而不是在单一文本框中输入正文。
2. 第一版即支持多人实时编辑、在线状态、协作光标、评论与离线合并。
3. 支持“指定协作者”和“活跃社区成员持链接编辑”两种共享模式。
4. 保持现有审核状态、角色权限、公开阅读和旧文章数据兼容。
5. 公开文章使用轻量、安全的静态内容，不加载完整编辑器和协作代码。
6. 桌面端形成接近成熟文档产品的工作台，移动端保留完整但重新组织的编辑能力。

## 技术选择

采用以下开源核心：

- BlockNote Core：React 块编辑器、命令菜单、格式化工具栏、表格、媒体块和评论界面。
- Yjs：共享文档数据结构、并发合并与离线同步。
- Hocuspocus：Yjs WebSocket 协作服务、身份验证和持久化钩子。
- Supabase Auth：连接身份和账号会话。
- Supabase Postgres：文章、协作者、分享链接、版本和 Yjs 二进制状态。
- Redis：生产环境多实例之间的协作消息与 awareness 分发。

选择 BlockNote Core 而不是 Tiptap 或 Lexical，是因为它以开源许可提供更完整的文档编辑器体验，能够减少从底层拼装块菜单、拖拽手柄、表格和格式工具栏的工作量；协作层仍基于通用的 Yjs，后续不会被单一托管服务锁定。第一版不使用 BlockNote XL 的商业或 GPL 功能。

## 编辑器体验

### 工作台结构

文章编辑页从普通表单升级为宽版文档工作台：

- 顶部固定文档栏：稳定返回、文章状态、保存状态、协作者、分享、保存版本和提交审核。
- 标题区：文章标题和摘要直接在正文上方编辑，不再被分隔成多个表单卡片。
- 正文区：居中的纸张式内容列，周围留出评论、历史版本和协作者面板空间。
- 侧面板：评论、版本历史和分享设置按需打开，不同时挤压正文。

顶部返回始终指向 `/community/stories`，社区品牌入口与官网入口继续由现有 CommunityChrome 提供。直接打开深层编辑链接时仍有稳定退出路径。

### 内容能力

第一版支持：

- 普通段落、一级至三级标题。
- 项目列表、编号列表、待办列表和可折叠内容。
- 引用、提示块、分隔线和代码块。
- 表格。
- 图片、视频、音频和文件附件。
- 链接、粗体、斜体、下划线、删除线、文字颜色和高亮。
- 富文本粘贴、Markdown 快捷输入、撤销与重做。

输入 `/` 打开块命令菜单。选择文字时显示浮动格式工具栏；移动到内容块旁时显示拖拽手柄，可排序、复制、转换和删除块。

媒体继续使用现有社区媒体服务。第一版不允许执行脚本、任意 HTML 或未审核 iframe。

### 实时协作与评论

编辑器展示在线协作者头像、实时光标、选区和连接状态。协作者能够针对内容建立评论线程、回复、解决和重新打开评论。

Yjs awareness 只承载临时在线状态，不作为永久数据库记录。评论作为业务数据单独保存，以便权限审计、通知和历史追踪。

### 双语

编辑器工具栏、命令菜单、状态、错误、分享面板、评论和版本历史随现有 `LanguageContext` 在中文与英文之间完整切换。用户输入的文章内容不自动翻译。

## 协作者与分享权限

### 角色

- 所有者：文章创建者，可邀请成员、撤销成员、切换分享模式、提交审核和创建修订。
- 指定协作者：由所有者邀请且 Membership 有效的社区成员，可编辑和评论。
- 持链接成员：所有者开启链接编辑后，已登录且 Membership 有效的社区成员可编辑。
- 审核者与管理员：继续使用现有 `field_notes.review`、`field_notes.edit_any` 等权限进入审核、批注或管理流程。

互联网访客、未登录用户、Membership 非 active 的账号，即使持有分享链接也不能编辑。

### 分享链接

分享链接使用高熵、不可猜测的令牌；数据库只保存令牌哈希。所有者可以撤销、轮换和设置有效期。分享链接只放宽“是否必须被单独邀请”，不绕过登录、Membership、文章状态或服务端权限检查。

### 状态约束

| 文章状态 | 所有者与普通协作者 | 审核人员 |
| --- | --- | --- |
| 草稿、退回修改 | 可编辑、评论 | 可查看、评论 |
| 已提交、审核中 | 默认只读，可评论 | 按审核权限编辑或批注 |
| 已批准、已发布 | 只读 | 通过“重新打开修订”后修改 |
| 已归档 | 只读 | 管理员可恢复 |

服务端是权限最终来源。状态或权限变化后，现有连接会重新验证并切换为只读；前端隐藏按钮不作为安全措施。

## 实时协作认证与部署

客户端连接 Hocuspocus 时提交 Supabase access token、文章标识和必要的分享令牌。协作服务在 `onAuthenticate` 中验证：

1. Supabase 会话是否有效。
2. Membership 是否为 active。
3. 用户是否是所有者、指定协作者、合格的持链接成员或具备管理权限。
4. 文章当前状态是否允许写入。

无写权限的合法访问者以只读连接进入；非法访问直接拒绝。所有持久化写入继续依赖数据库约束与 RLS，不能只依靠 WebSocket 握手。

生产环境可以将 Hocuspocus 部署到 Vercel WebSocket Function 或独立常驻服务。由于新连接不保证落到同一实例，多实例使用 Redis 扩展传播协作更新和 awareness，Supabase Postgres 保存永久 Yjs 文档。开发环境允许单实例运行，但上线前必须启用跨实例同步。

## 数据模型

### 文章快照

保留现有 `field_notes.content text`，并增加：

- `content_json jsonb`：可移植、可版本化的 BlockNote JSON 快照。
- `content_html text`：服务端生成并完成安全清理的公开展示快照。
- `content_schema_version smallint`：内容结构版本。

`content` 继续保存纯文本结果，用于旧代码兼容、摘要、搜索和安全降级。协作编辑时的实时源是 Yjs 文档；每次检查点把它物化为 JSON、纯文本和 HTML。

### 协作文档

在私有 schema 中增加 `field_note_collab_documents`，以 `note_id` 唯一关联文章，保存 Yjs 二进制状态、schema 版本和更新时间。Hocuspocus Database 扩展负责读取和防抖写入该记录。

### 协作者和链接

增加受 RLS 保护的业务表：

- `field_note_collaborators`：文章、用户、角色、邀请人、创建时间和撤销时间。
- `field_note_share_links`：文章、令牌哈希、分享模式、启用状态、有效期和轮换信息。
- `field_note_comments` 与回复关系：锚点、内容、作者、解决状态和时间。

### 版本历史

扩展现有修订记录，使每个版本同时保存 JSON、HTML、纯文本和内容 schema 版本。恢复旧版本时创建新修订，不覆盖或删除历史记录。

## 保存与恢复

### 三层保存

1. 每次编辑立即进入 Yjs 共享状态。
2. 浏览器 IndexedDB 保存本地副本，支持刷新和临时断网恢复。
3. 停止输入约 1–2 秒后，将增量同步到 Hocuspocus 和数据库。

文档栏明确展示“正在保存、已保存、离线编辑、正在重新连接、同步失败”。手动保存、提交审核和发布前强制建立完整检查点。

### 离线与权限变化

断网期间允许已授权用户继续编辑；恢复连接后由 Yjs 合并并发更新。重新连接时必须重新验证权限。如果用户离线期间权限被撤销，未同步内容保存为本地恢复副本，不写入受保护文章。

### 检查点

以下事件创建版本：

- 手动保存版本。
- 有实际修改时的定期自动检查点。
- 提交审核、审核退回、批准和发布。
- 恢复旧版本之前。

第一版提供版本列表、操作者、时间、状态、预览和恢复。逐字或逐块差异对比作为后续增强。

## 公开阅读与旧内容

公开文章页面不加载 BlockNote 编辑器、Yjs 或协作客户端，而是渲染已发布版本的安全静态快照。编辑中的 Yjs 文档、评论、光标和在线状态不会暴露到公开页面。

当前本地 Field Notes 内容继续由现有仓库读取；已发布的社区文章增加数据库读取路径，并通过稳定 slug 进入公开文章页。后续可以再统一两类内容仓库，本次不要求一次性迁移全部静态内容。

旧纯文本文章第一次进入编辑器时转换为段落块，同时保留原始 `content`。转换采用幂等标记，失败时继续展示旧编辑器或只读正文，不破坏已有文章。

## 移动端与无障碍

- 手机顶部工具栏仅保留返回、保存状态和更多菜单。
- 文字选择工具栏靠近软键盘，块菜单、媒体、评论和版本历史使用底部抽屉。
- 表格在正文内横向滚动，不造成整页横向溢出。
- 协作者头像折叠为人数入口。
- 触控目标不小于 44px，键盘焦点清晰，图标按钮具有可访问名称。
- 编辑器遵守 `prefers-reduced-motion`，连接和保存状态不只依赖颜色表达。

## 错误处理

- WebSocket 中断：进入离线模式，保留本地内容并退避重连。
- 持久化失败：显示可重试状态，不清空本地副本。
- 页面离开：仍有未持久化内容时显示提醒。
- 多标签页：提示用户，但允许 Yjs 安全合并。
- 图片失败：在对应媒体块内重试，不阻塞文字编辑。
- 文章状态改变：服务端拒绝后续写入，客户端切换只读并保留恢复副本。
- 提交审核：只有完整快照写入成功后才能改变审核状态。

## 安全边界

- HTML 在服务端生成并清理，禁止脚本、危险 URL 协议和未允许的嵌入。
- 限制文档大小、单次粘贴大小、附件类型和附件体积。
- 分享令牌可撤销、可过期，并在存储前哈希。
- 协作连接、评论、版本恢复和分享变更进入审计记录。
- 所有敏感表使用 RLS；私有 Yjs 表不暴露给普通 PostgREST 客户端。
- 发布只读取已批准的版本快照，编辑中的内容不能绕过审核出现在公开页面。

## 实施顺序

1. 增加内容快照、协作者、分享、评论、版本和私有协作文档 migration 与类型。
2. 建立 Hocuspocus 服务、Supabase token 校验、权限解析、持久化和 Redis 扩展。
3. 接入 BlockNote 编辑器、文档栏、保存状态、命令菜单和媒体上传。
4. 增加邀请成员、链接分享、实时 presence、协作光标和评论。
5. 增加自动检查点、版本预览、恢复和提交审核锁定。
6. 建立服务端快照物化、安全静态渲染和数据库公开文章路径。
7. 完成旧内容迁移适配、移动端、双语、测试和生产配置说明。

## 验证策略

自动测试覆盖：

- BlockNote JSON、Yjs 文档、纯文本和 HTML 的往返转换。
- 所有者、邀请成员、持链接成员、非活跃 Membership、访客和管理员权限矩阵。
- 草稿、审核中、退回、发布和归档状态下的读写行为。
- 令牌撤销、过期和轮换。
- 自动保存、断网重连、并发编辑、状态锁定和本地恢复副本。
- 旧纯文本文章转换与回退。
- 版本建立、预览和恢复。
- 公开渲染不包含编辑器代码、危险 HTML、评论或未发布内容。

浏览器验收至少使用两个独立账号和两个浏览器上下文，验证同时编辑、光标、评论、断网恢复、权限撤销和审核锁定。响应式验证覆盖约 1440px 桌面与 390px 手机，并确认页面无横向溢出。

工程验证包括 TypeScript、相关 ESLint、Vitest、数据库测试、生产构建和 Supabase security/performance advisors。

## 第一版验收标准

- 两个不同账号可以同时编辑，并看到彼此光标与内容变化。
- 断网编辑后能够重新连接并正确合并。
- 指定协作者与“活跃社区成员持链接编辑”均可正常使用。
- 非活跃 Membership、被撤销用户和普通访客不能写入。
- 提交审核后普通协作者立即只读，审核人员按权限继续批注或处理。
- 历史版本可以预览并恢复成新版本。
- 旧纯文本文章能够无损打开和继续编辑。
- 发布结果与批准的编辑器快照一致，刷新后不丢失。
- 390px 手机宽度没有页面级横向溢出，核心编辑功能可使用。
- 现有社区导航、审核、发布和双语流程继续通过测试。
