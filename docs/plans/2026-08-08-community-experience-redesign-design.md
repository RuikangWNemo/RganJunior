# 阿柑少年社群中枢体验重设计

日期：2026-08-08

## 背景

社群已经具备登录、资料完善、入群申请、成员首页、文章、伙伴、共练、消息、设置和管理审核等完整路由，但前端体验仍像一组彼此独立的功能页面：成员主导航只存在于部分页面，编辑、申请、设置和管理页面缺少稳定返回路径；社区品牌入口与官网入口不够明确；导航虽能随语言变化，页面正文、状态和反馈却仍以中文硬编码为主；页面普遍使用同一种白色大卡片，内容层级和互动反馈不足。

本次采用“社区中枢式改版”。目标是在不改变现有认证、会员、权限和 Supabase 数据逻辑的前提下，把所有 `/community` 页面组织成一个方向明确、完整双语、具有阿柑少年品牌感的社区产品。

## 设计目标

1. 用户从任意社区页面都能知道当前位置、返回上级、进入社区首页或返回官网。
2. 中 / EN 切换覆盖整页文案、状态、空页面、错误反馈、日期和时间，而不只覆盖导航。
3. 正式成员区在桌面和移动端都拥有清楚、可识别且稳定的主导航。
4. 登录、资料完善、申请、监护人确认和审核状态形成连续流程，不再出现无出口页面。
5. 在保留现有品牌气质的基础上提升视觉层级、互动感、反馈质量和无障碍表现。

## 信息架构

### 全局社区顶栏

所有 `/community` 路由共用统一社区顶栏，包括登录、注册、资料完善、申请、申请状态、监护人确认、成员区、设置和管理页面。

顶栏提供：

- 阿柑少年标识与 Community 品牌；点击后进入 `/community/enter`，由现有状态解析器分发至正确页面。
- 当前栏目或流程上下文。
- 中 / EN 语言切换。
- “返回官网”入口，稳定指向 `/`。
- 已登录用户的账号菜单；根据状态提供设置、管理入口和退出登录等操作。

全局顶栏不取代业务页面的上级返回入口。品牌入口负责“回到正确的社区落点”，官网入口负责“离开社区”，页面返回负责“回到稳定上级”。

### 正式成员区

成员区继续包含六个核心区域：

```text
社群首页 / Community
文章 / Stories
伙伴 / People
共练 / Practice
消息 / Messages
设置 / Settings
```

桌面端使用保持可见的侧栏。移动端底部导航保留首页、文章、伙伴、共练和消息五个高频入口，每项同时显示图标与文字；设置进入顶部账号菜单，避免六个无文字图标造成识别困难。

有相应权限的用户在侧栏和账号菜单中看到管理入口。管理页面不成为普通用户的默认落点。

### 次级页面与稳定返回

页面层级由集中式路由元数据定义，不依赖浏览器是否存在历史记录。

- 新建或编辑文章：面包屑为“社群 / 文章 / 写作或编辑”，返回 `/community/stories`。
- 设置：返回 `/community`，正式成员仍保留成员导航。
- 伙伴发起会话：进入消息后可返回伙伴目录或社群消息列表。
- 申请与监护流程：显示当前位置、上一步、下一步和返回官网。
- 申请状态：可返回资料或进入社区落点，具体行为继续由成员状态决定。
- 管理审核：显示“社群 / 管理 / 当前任务”，提供返回社群首页的稳定入口。

浏览器返回继续遵守真实历史记录；页面内返回按钮始终指向稳定上级，保证直接打开深层链接时也不会迷失。

### 入群流程

注册、资料完善、社群申请、监护确认和审核状态使用统一步骤表达：

```text
建立账号 → 完善资料 → 提交申请 → 安全确认（按年龄需要）→ 等待审核
```

每个页面明确展示当前步骤、下一步含义和退出路径。流程显示不改变现有年龄分流、监护人同意或权限守卫。

## 双语策略

采用“中 / EN 切换，整页随语言切换”。

- 建立集中式社区文案表和轻量读取方式，按 `LanguageContext.lang` 返回当前语言。
- 社区顶栏、导航、页面标题、描述、按钮、表单标签、帮助文字、空状态、加载、错误与成功反馈全部进入文案表。
- 业务状态使用稳定内部值，界面通过状态映射显示本地化名称。
- 日期和时间使用当前语言对应 locale 格式化。
- 语言选择沿用现有全站语言状态及持久化机制。
- 品牌专名可以保留必要的中英文组合，其余界面不在同一页面重复堆叠两种语言。

数据库内容如成员自行填写的简介或文章正文不自动翻译；本次只保证产品界面完整双语。

## 视觉方向

主题为“营地中的社群中枢”：保留阿柑少年的自然、人文和编辑感，同时提供成熟数字产品所需的清晰度。

- 暖米白作为纸张底色，森林绿承担结构与导航，柑橘橙只用于主要操作和关键状态。
- 使用轻微颗粒、低对比手绘路径或有机色块建立空间感，不使用大面积渐变和厚重玻璃拟态。
- 页面由环境背景、结构容器和内容卡三层组成，避免所有内容都被包在相同白色大卡片中。
- 大标题保持品牌衬线字体，功能文字使用清晰无衬线字体；紧凑状态与说明通过字号、字重和留白建立层级。
- 顶栏使用现有吉祥物品牌资产。装饰服务于方向和情绪，不遮挡信息或形成额外点击竞争。

## 页面表达

### 社群首页

首页从功能入口集合升级为成员仪表盘：

- 个性化欢迎和当前账号上下文。
- 需要处理的事项或近期通知。
- 写文章、认识伙伴、参加共练、成员消息四个主要行动入口。
- 近期内容和活动的清晰空状态。

### 伙伴

伙伴卡强化自然名、展示名、双语姓名、所在地和简介层级。首字头像作为无图片时的稳定占位；“发消息”是明确的次级动作，并对本人、不可发消息和读取失败提供对应状态。

### 文章

列表突出标题、更新时间、可见范围和审核状态。新建与编辑页面使用清晰面包屑、保存反馈和稳定返回，不因保存后跳转而失去上下文。

### 共练

共练卡使用日期、时间、席位进度和参与状态建立信息层级。加入、取消、候补与会议信息解锁均提供即时反馈。

### 消息

桌面端采用会话列表与消息内容双栏关系；移动端在会话列表和内容之间使用明确返回。空会话、发送中、发送失败和不可联系状态有完整反馈。

### 设置与管理

设置按个人资料、隐私与账号分组，不再呈现为孤立表单。管理页面共享顶栏、面包屑和管理上下文，同时保持敏感信息的现有权限边界。

## 互动与动效

- 卡片使用轻微悬浮、边框变化和箭头位移反馈，不采用大幅缩放。
- 页面和步骤切换使用短距离淡入与位移，持续时间克制。
- 保存、加入、退出、发送和审核动作具备忙碌、成功与失败反馈。
- 加载状态优先使用与最终布局接近的骨架，失败状态提供可执行的重试入口。
- 移动端触控目标不小于 44px；底部导航显示文字标签。
- 所有动效遵守 `prefers-reduced-motion`，键盘焦点清晰可见，图标按钮具备可访问名称。

## 前端架构

### CommunityChrome

新增统一的社区外壳组件，覆盖所有社区路由，负责顶栏、品牌入口、官网入口、语言切换、账号操作和环境背景。它不负责成员权限判断或业务数据。

### CommunityShell

重构现有成员壳层，只负责正式成员区的桌面侧栏、移动底栏和成员内容布局。导航项根据语言和权限显示，继续通过 React Router 的 active state 标识当前位置。

### CommunitySurface

扩展为统一页面模板，支持：

- 本地化 eyebrow、标题与描述。
- 面包屑和稳定返回操作。
- 标题区主要动作。
- 主内容、辅助信息和不同宽度布局。
- 页面级加载、错误和空状态插槽。

具体业务卡片仍由各页面负责，避免把所有视觉判断塞进一个万能组件。

### 路由元数据与文案

建立集中式社区路由元数据，描述当前栏目、面包屑、稳定上级和移动端返回目标。建立集中式双语文案资源与状态映射。两者保持纯前端、可测试，并避免改动数据库模型。

## 数据与错误处理

- 保留所有现有 services、Supabase Auth、成员状态解析、RLS 和权限守卫。
- 读取失败不再静默伪装成空数据；页面区分加载、空结果和错误，并提供重试。
- 提交按钮在请求期间禁用，保留原始表单内容；成功后先提供明确反馈，再执行必要跳转。
- 对用户显示的错误继续避免泄露邮箱、手机号、账号存在性、监护人资料或后台审核备注。
- 本次不增加自动翻译服务，不修改用户生成内容，也不修改数据库 schema 或 migration。

## 响应式行为

- 桌面：全局顶栏 + 固定成员侧栏 + 自适应主内容。
- 平板：紧凑顶栏 + 可折叠或简化侧栏，根据内容宽度切换。
- 手机：紧凑顶栏显示返回与语言；成员主区域使用带文字的五项底栏；表单和消息区按自然阅读顺序单列。
- 固定导航为设备安全区预留空间，主内容底部 padding 防止被遮挡。

## 验证策略

自动测试覆盖：

- 全局社区顶栏在公开流程页、成员页和管理页均可用。
- 品牌入口、官网入口和每类次级页面的稳定返回目标。
- 中 / EN 切换后导航、页面、状态、空页面和操作文案同步变化。
- 移动底栏包含可见文字标签，设置可从账号菜单到达。
- 权限不足时不显示管理入口，已有路由守卫行为保持不变。
- 业务读取区分加载、空状态和错误，重试可再次触发请求。

工程验证包括应用 TypeScript、相关 ESLint、完整 Vitest 和 Vite production build。浏览器验证覆盖约 1440px 桌面和约 390px 手机宽度，至少走查登录页、入群流程页、成员首页、文章编辑、伙伴、共练、消息、设置和管理入口。

## 验收标准

- 任意社区页面都能返回稳定上级、进入正确社区落点并返回官网主页。
- 所有社区产品界面完整支持中 / EN 切换，切换后没有明显中文硬编码残留。
- 桌面侧栏和移动底栏易于识别，移动端不再依赖六个无文字图标。
- 首页、伙伴、文章、共练、消息和设置具有各自清楚的信息层级，而非同一模板的重复。
- 加载、空、失败、忙碌和成功状态清晰可见。
- 不改变认证、会员、监护人确认、审核、权限或 Supabase 数据行为。
- 自动测试、类型检查和生产构建通过，并完成桌面与移动浏览器走查。
