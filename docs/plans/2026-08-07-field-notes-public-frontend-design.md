# 田野笔记公共前端设计

日期：2026-08-07

## 目标

在官网“发起人故事”之后新增“田野笔记 / Field Notes”一级菜单，先完成不依赖建设中社区后台的公共阅读体验。页面用于呈现阿柑少年来自少年、家长、伙伴、合作者与发起人的真实观察、复盘和研究，让项目的思想深度可以被浏览、检索和持续积累。

本阶段只建设公共前台。成员投稿继续归入长期社群平台的 `/community/stories`，审核、修改、发布和题材管理继续归入 `/admin/stories`。三者复用现有 `field_notes`、`people`、`identity_labels` 和 `topics` 数据模型，不建立第二套文章系统。

## 信息架构

```text
官网导航
└── 田野笔记
    ├── 精选文章  /field-notes
    └── 全部文章  /field-notes/all

文章详情          /field-notes/:slug
```

精选文章页强调编辑策划和思想线索；全部文章页强调查找效率。两页共享搜索、人物和题材筛选，并把查询状态写入 URL，便于返回、分享和未来服务端查询。

## 内容分类

人物维度沿用公共身份与人物档案：

- 创始人 Nate
- 阿柑少年伙伴
- 家长
- 合作者

题材维度与现有数据库种子保持一致，并在前台使用更具阅读感的中文名称：

- 生活随笔与反思
- 共创营复盘与启发
- 研究内容与实验设计

首批示例内容覆盖 Nate 的中英文随笔、生活共创营复盘、孩子行动卡与原话、家长观察、生态与 CSA 研究、低碳生活实验和 John Locke 论文延伸思考。示例数据仅承担接入前的界面验收，不伪装成已发布的真实用户投稿。

## 页面设计

### 精选文章

页面采用“田野档案 / 独立刊物”视觉语言，而不是常规博客卡片墙：纸张底色、森林绿、细分隔线、文章编号、日期、人物署名和宽松留白。

首屏包含栏目名称、简短宣言、当前文章数量和搜索入口。随后是一篇主编精选文章与两篇次级文章，建立本期重点。下方提供“按人物 / 按题材”切换：

- 按人物时，横向排列人物索引；选择人物后，在同一行下方展示其文章。
- 按题材时，显示三个题材入口与相应文章数量，再展示当前题材文章。

### 全部文章

全部文章使用紧凑的编辑型列表。每条显示序号、标题、摘要、作者、人物身份、题材和日期。搜索与筛选在桌面端并排，在移动端纵向排列。结果数和清除筛选操作始终可见。

### 文章详情

详情页延续现有伙伴之声的阅读排版，但使用田野笔记自己的元信息结构：作者、人物身份、题材、日期、阅读时间和内容状态说明。正文支持标题、段落、引用、列表和行动卡式摘录。结尾提供同作者文章和同题材文章的继续阅读入口。

## 组件与数据边界

公共页面只依赖一个 `FieldNoteRepository` 形状：

```text
listPublishedNotes(query)
getPublishedNoteBySlug(slug)
listPublicPeople()
listActiveTopics()
```

接入前使用本地 fixture provider，并让字段命名与 Supabase 查询结果对齐。后续接入时由 Supabase provider 完成数据库行到前端视图模型的映射，页面组件和路由保持不变。

主要组件：

- `FieldNotesHero`：栏目标题、宣言和搜索。
- `FeaturedNoteLayout`：一主两次的精选编排。
- `FieldNoteExplorer`：人物/题材切换、筛选和结果。
- `PersonRail`：横向人物索引。
- `FieldNoteCard` 与 `FieldNoteRow`：精选和全部文章两种密度。
- `FieldNoteArticle`：阅读页。

## 状态与降级

- 加载中保留稳定骨架，避免版面跳动。
- 搜索无结果时保留当前条件并提供一键清除。
- 数据请求失败时显示克制的重试提示，不暴露 Supabase 错误文本。
- 本地 fixture 与未来真实数据都通过同一仓库接口读取。
- 图片缺失时使用题材色块、文章编号和作者首字母组成封面，不依赖占位图库。
- `prefers-reduced-motion` 下关闭位移动画，只保留透明度变化。

## 响应式与无障碍

- 导航桌面端提供“精选文章 / 全部文章”下拉菜单，移动端放入折叠菜单。
- 人物索引可以键盘操作并支持横向滚动；当前人物使用 `aria-pressed` 表达。
- 搜索框有可见标签和清除按钮，结果区域使用礼貌的动态播报。
- 文章卡整体不嵌套交互控件，点击目标不少于 44px。
- 移动端保留编辑感，但将主次文章改为单列，避免横向正文滚动。

## 验证

- 单元测试覆盖导航顺序、子菜单、路由、搜索、人物筛选、题材筛选、清除条件、空状态和未知文章。
- 类型检查确认本地数据契约可以映射到现有 Supabase 类型。
- 构建验证新增路由与内容资源。
- 浏览器分别在桌面与移动尺寸检查首屏层级、人物横排、筛选状态、长标题、中文/英文切换和文章阅读宽度。
