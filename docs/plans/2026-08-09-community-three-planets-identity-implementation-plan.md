# 社群伙伴三星系统与身份管理实施计划

依据：`docs/plans/2026-08-09-community-three-planets-identity-design.md`

## 实施边界

- 保留现有 Supabase Auth、年龄分流、监护人确认、入群申请、成员资格和权限角色。
- `raw_user_meta_data` 只用于捕获注册时的自报身份，任何 RLS、权限或正式星球归类都不得信任该值。
- 正式星球只读取管理员确认后的 `person_identity_labels`。
- 保留工作区当前未提交的监护人流程、协作编辑和 About 页面改动；新迁移必须建立在最新本地迁移之上，并保留最新审核函数行为。

## Phase 1：数据库身份基础与安全接口

1. 使用 `supabase migration new community_three_planets_identity` 创建迁移文件。
2. 扩展 `identity_labels`：增加稳定星球映射、是否允许注册选择和是否为核心身份等配置字段。
3. 幂等写入五个核心身份：发起人、青年共创伙伴、参与者、成人支持团队、家长守护团；只有后四个允许注册选择。
4. 新建私有自报身份表，保存用户、标签、主／副标记、状态、声明与审核时间；不向 Data API 公开。
5. 增加注册捕获触发器：从 Auth 元数据中读取身份 slug，只接受当前可注册身份，忽略或记录非法值，永不写入正式身份表。
6. 增加公开只读 RPC，向未登录注册页返回当前允许选择的身份名称、说明、颜色和星球映射。
7. 扩展申请列表 RPC，返回自报主身份和副身份。
8. 替换最新申请审核函数：通过申请时必须提交一个已确认主身份，校验副身份去重；在同一事务中创建成员资格并写入正式身份标签。发起人只能由具备 `people.manage` 或对应管理权限的调用者确认。
9. 增加管理员 RPC：读取／更新标签配置、查询成员身份、设置正式主副身份、读取待补齐队列和身份统计。
10. 扩展伙伴目录 RPC，返回已确认的身份标签和星球映射，并排除没有有效主身份的历史成员。
11. 对所有新函数执行显式 `REVOKE` / `GRANT`；`SECURITY DEFINER` 函数固定空 `search_path` 并在函数体内做调用者权限检查。
12. 复用现有身份标签与成员身份审计触发器，并为自报身份记录补充审计。

## Phase 2：类型与前端服务契约

1. 更新 `src/lib/supabase/database.types.ts` 中受影响的表与 RPC 类型，同时保留当前未提交的监护人类型改动。
2. 新建或扩展身份服务，提供：
   - 注册身份选项读取。
   - 管理员标签配置读取和更新。
   - 成员身份查询与调整。
   - 三星身份统计读取。
3. 扩展 `SignUpInput`，传递一个主身份 slug 与副身份 slug 数组到 Auth 元数据。
4. 扩展成员目录 `CommunityPerson` 契约，包含主身份、全部已确认身份和星球数组。
5. 扩展申请审核服务，让批准操作必须携带管理员确认后的主副身份。

## Phase 3：注册与审核界面

1. 将注册流程改为“身份 → 年龄 → 账号”三步，默认停留在身份选择。
2. 身份步骤从服务端读取四个允许身份；使用单选设置主身份，并允许勾选其他身份作为副身份。
3. 在确认区明确标注“注册选择需要管理员审核，不会直接获得身份权限”。
4. 更新注册测试：必选主身份、无发起人选项、可选副身份、完整提交参数和步骤返回。
5. 在管理员申请卡中展示自报主副身份，并提供确认后的主身份与副身份选择器。
6. 通过按钮在没有确认主身份时保持禁用；审批调用携带确认结果。
7. 保留未成年人身份核验与监护人确认的现有阻断逻辑，并与身份标签确认共同生效。
8. 更新管理员审核测试，覆盖身份默认值、管理员调整、发起人设置与重复提交锁。

## Phase 4：管理员身份与统计工作台

1. 新增 `/community/admin/identities`，由 `people.manage` 权限守卫。
2. 页面包含三部分：
   - 星球与身份统计：自报、已确认、主身份不重复人数、跨星球重叠和待补齐人数。
   - 身份标签配置：中英文名、说明、颜色、顺序、启用状态、是否允许注册选择和星球映射。
   - 成员身份管理：搜索成员、设置唯一主身份、增减副身份、显示最后调整时间。
3. 发起人标签不允许开启注册自选；核心 slug 不允许编辑或删除。
4. 更新路由元数据、桌面侧栏与账号菜单中的管理入口。
5. 为工作台添加加载、保存中、保存成功、读取失败和空队列状态。

## Phase 5：连通三星伙伴体验

1. 定义三星配置：`youth`（阿柑少年圈）、`support`（成人支持团队）、`guardian`（家长守护团）。
2. 新增连通三星导航组件：
   - 默认选中阿柑少年圈。
   - 三颗星球始终可见，成人支持团队居中。
   - 连接带显示固定组织关系，交叠计数来自真实多身份成员。
   - 点击星球或顶部切换按钮改变当前焦点。
3. 使用 `?planet=youth|support|guardian` 保持选择；无效值回退到 `youth`。
4. 按当前星球过滤成员后复用现有懒加载 3D 成员星球；不把三套 WebGL 场景同时加载。
5. 当前星球成员在 3D 场景、详情面板、可访问索引和名单视图中保持同步。
6. 成员卡与详情显示主身份、副身份和多色身份环；阿柑少年圈内部区分发起人、青年共创伙伴和参与者。
7. 没有成员时仍显示三颗星球、连接、说明和空状态。
8. WebGL 失败时保留连通二维三星导航与完整名单。
9. 扩展社区 CSS，覆盖桌面、手机、触屏、键盘焦点和减少动态效果。
10. 更新伙伴页测试：默认星球、三个切换方式、查询参数、过滤、多身份交叠、空星球、名单同步和 WebGL 降级。

## Phase 6：验证与交付

1. 新增数据库测试，覆盖：
   - 注册只能自报四个允许身份。
   - 自报身份不能授予权限或进入伙伴目录。
   - 普通用户无法自设发起人。
   - 管理员批准时原子化确认身份并创建成员资格。
   - 主身份唯一，副身份去重。
   - 多身份成员产生正确的星球与交叠统计。
   - 历史无主身份成员进入待补齐队列。
   - 非管理员无法读取敏感声明或修改标签。
2. 运行定向 Vitest，再运行应用 TypeScript、API TypeScript、完整 Vitest 和 production build。
3. 在可用的数据库环境运行身份迁移测试与安全检查；若远程环境未获授权，仅执行本地静态验证并明确列出待部署验证。
4. 启动开发服务器，在约 1440px 与约 390px 视口走查注册、申请审核、身份工作台和伙伴三星页。
5. 验证键盘焦点、减少动态效果、无 WebGL 降级和移动端触控切换。
6. 最终检查 `git diff`，确保没有覆盖或夹带工作区中与本需求无关的既有改动。
