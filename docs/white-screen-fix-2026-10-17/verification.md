# 切页白屏与空白区域修复（2026-10-17）

用户补充：Windows 电脑切换页面时偶发整页白屏，或页面上下出现一块空白。没有具体浏览器版本、截图和 Windows 实机环境，因此不能认定唯一原因或宣称已完成 Windows 验收。

## 代码发现与修复

1. **加载期间确实是空容器。** App 的 Suspense fallback 只有高度与背景，没有可见内容；首次 HTML 的 root 同样为空。现在首包加载有静态中英文提示，切页加载有可读状态，超过 8 秒提供重新加载和返回首页。
2. **页面模块下载失败没有错误边界。** 懒加载 import 拒绝或页面渲染异常可能卸载 React 树。新增页面与外壳错误边界：页面失败时保留导航、显示恢复入口；不会自动刷新循环。Vite 官方文档也说明发布后旧页面引用已删除模块可造成此类错误：https://vite.dev/guide/build#load-error-handling 。本轮没有证据表明此次用户故障一定由旧缓存引起。
3. **全站透明与浏览器存储强耦合。** 语言切换先把整个应用 opacity 设成 0，在 localStorage 写入后才安排恢复；写入抛错会使恢复不执行。移除整站淡出，语言立即切换，存储读写失败均退回内存状态。移除整页不必要的 will-change: opacity，减少大合成层。
4. **正文块依赖滚动回调才可见。** 首页信念、项目标题、发起人介绍、社群文字及发起人故事存在 opacity:0 初态。滚动观察回调延迟会留下有高度但透明的内容块。修改为正文始终可见，仅保留轻微位移动画；不依赖动画执行成功才显示内容。
5. **滚动位置跨页残留。** 自定义桌面滚动只限制目标位置，没有限制当前插值位置；长页面变短后仍可能继续沿旧位置计算。现在同时限制两端，导航、原生滚动、键盘和指针操作会取消旧惯性。RouteViewport 在 DOM 挂载、延迟页面揭示时使用 layout effect 即时复位或定位锚点，避免之前固定 80ms 等待早于真实加载结束；页面存续期间禁用浏览器自动历史位置恢复。滚动缺陷能解释错位与跳动，不能单独证明用户截图中的白块来源。

## 验证

- 33 项测试通过（9 个文件）：加载提示、超时恢复控件、模块下载失败、错误后导航恢复、延迟锚点、语言存储失败、观察器不回调时正文仍可见、Windows 常见按行 wheel 输入、长转短页面滚动、已有首页／项目／故事回归。
- App TypeScript 检查通过；针对修改的组件 ESLint 无错误，仅 LanguageContext 导出 hook 的既有 Fast Refresh 提示。
- 本机正式构建通过（保留已有 chunk 大小警告）。没有访问 ECS 或部署。
- 本地已构建网站，以隔离 HTTP 服务对 Actions 页面模块人为延迟 12 秒：立即显示加载提示，期间后退恢复首页且 scrollY=0；最终项目页正常出现，加载占位消失，1280px 视口无横向溢出。
- 对同一模块返回 HTTP 503：显示可读失败提示与重新加载／返回首页，顶部导航仍可用，点击首页可恢复。
- 在项目页滚动过程中切回首页：scrollY=0；首页三个主要正文块无 opacity:0。
- 截图 `loading-state.png` 为慢网模拟；`download-failure.png` 为人为阻断下载模拟，不代表线上故障截图。
